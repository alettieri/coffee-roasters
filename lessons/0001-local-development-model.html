Local development: what runs where

The practical model is local-first: application, Cloudflare emulation, and PostgreSQL run on your machine. Neon enters the workflow for previews and release verification.

The fast loop

Browser ↓ localhost Nuxt + Vue ↓ Nitro running with local workerd/Miniflare emulation ├── local R2 binding → files on this machine ├── local queue binding → locally handled messages └── DATABASE_URL → PostgreSQL Docker container

Start PostgreSQL with Docker Compose, then run pnpm dev. Nitro reads the Cloudflare binding definitions and emulates them through Miniflare. Application code accesses bindings through the request event in the same shape used in production. The application connects to the PostgreSQL container through a local connection string.

Where Neon enters

Neon remains the deployed PostgreSQL provider. Preview environments and migration checks use isolated Neon branches with their own connection strings. This catches provider-specific differences before production while keeping daily development fast, offline-capable, and disposable.

The production-runtime check

pnpm build ↓ Nitro cloudflare_module output ↓ wrangler dev ↓ local workerd preview using production-shaped configuration ↓ release verification against an isolated Neon branch

Use this slower loop before merging or deploying. It catches code that works in the convenient development server but fails under the actual Workers runtime, build output, bindings, or compatibility flags.

The rule to remember

Use Docker PostgreSQL and pnpm dev for the fast local loop. Use Wrangler/workerd plus an isolated Neon branch to prove runtime and provider compatibility before deployment.

Quick retrieval check

  1. If you upload a photo during ordinary local development, should it appear in the production R2 bucket?
  2. If a migration succeeds against local Docker PostgreSQL, has Neon changed?
  3. If a feature works locally, what two compatibility checks remain before deployment?

Answers: no; no; run the Cloudflare build through Wrangler/workerd and verify migrations against an isolated Neon branch. Ask the agent about any part of the flow that remains unclear.
